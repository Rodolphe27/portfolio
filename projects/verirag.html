Project 01 · Open source

VeriRAG — Verified Answers from Documents

Python LangGraph Multi-agent RAG MCP Evaluation Docker

A question answering system that checks its own answers. Most document chatbots return fluent text whether or not the documents support it. VeriRAG adds a second agent whose only job is to catch that: an answer is shown only if every claim in it is backed by a quote that really exists in a retrieved passage. Otherwise the system says it is not sure, explains why, and points to the closest text.

The agents. A LangGraph graph connects hybrid retrieval (local multilingual embeddings plus BM25, merged with Reciprocal Rank Fusion), a writer agent that splits its answer into single claims, and a verifier agent that must quote the proof for each claim. The code then checks that the quote is in a retrieved passage, so a made-up justification cannot pass. Failed claims go back to the writer as feedback, at most twice, and then the system refuses. Citations in the final answer come from the verified quotes, not from what the writer said.

Architecture. One program with strict module borders: a modular monolith with ports and adapters around the model, the search and the log. Gemini and Anthropic sit behind one interface and are switched with a setting. The dependency rules are enforced in CI with import-linter, and five decision records explain the choices and their costs.

Interfaces. A command line (index, ask, evaluate, serve), a Python API, an MCP server that offers the search and the verified answers as tools to AI applications, and a Docker image with the model and a sample index inside.

Measured, not claimed. On 35 questions about the EU AI Act (27 with an answer, 8 without), hybrid search found a correct article in the top four for 96% of the questions, against 93% for meaning-only and 74% for keyword-only search. With the whole system and Gemini, 24 of 27 questions were answered with a correct article, 3 were refused, and all 8 off-topic questions were refused. No wrong answer was released. The three false refusals are explained in the evaluation page, together with the limits: the question set is small and the wording of each answer is not graded automatically.

Engineering. More than 200 tests that run in seconds with scripted fake models and no network. CI runs the style check, strict type checking, the architecture rules and the tests, and also builds and smoke-tests the Docker image. The work was planned as 27 small issues on a public project board and committed in small steps.
