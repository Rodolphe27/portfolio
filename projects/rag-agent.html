RAG Document Agent — Python

Python RAG Embeddings BM25 LLM agents Gemini Claude

A retrieval-augmented generation (RAG) system I wrote in plain Python to understand how each part works, instead of hiding it behind a framework. It answers questions about my own documents — lecture slides, PDFs, notes — and always shows the file and page the answer came from. It connects to my bachelor-thesis topic, where an AI agent has to work with tools in a controlled way.

Ingest. Text and Markdown files and PDFs are read page by page with pypdf, so page numbers survive. The text is cut into overlapping chunks and embedded locally with a multilingual MiniLM model (fastembed), which works for German and English and costs nothing to run. Chunks and vectors go into one JSON index. A file hash decides what has changed, so only new or edited files are embedded again.

Hybrid retrieval. A question is searched in two ways: by meaning (cosine similarity on the vectors) and by keywords (BM25, written from scratch with NumPy). The two rankings are merged with Reciprocal Rank Fusion. Words are cut to six letters so that German word forms such as “kritischem” and “kritische” still meet. If no passage is close enough, the system says “I do not know” instead of guessing.

Generation. The best passages are numbered and sent to Gemini or Claude through plain REST calls. Requests retry with waiting on 429 and 5xx errors and fall back to another model when the first one stays overloaded.

Evaluation. A small tool measures retrieval alone, without calling a language model: does the right file and page appear in the top results (hit@1, hit@4, MRR), and are out-of-scope questions refused. This makes a change to the search something I can measure instead of guess.

Agent. On top of the same retrieval sits a tool-using agent. The model works in a loop with three read-only tools — list documents, search, read a page — and decides itself when to search again with other words or read a full page. It has a step limit and then must answer with citations. Tool calls are printed, so its behaviour can be followed.

This is a learning project and still in progress. Next step is to compare hybrid and meaning-only search on a larger set of real documents.
