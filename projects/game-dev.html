2D Action Game — C# / MonoGame

C# MonoGame .NET 8 State Pattern Factory Pattern

A 2D action game built in C# on the MonoGame framework (DesktopGL, .NET 8), without a higher-level engine on top. It started as a university game-development project and I have kept building on it since.

The code is split into clear layers: a domain layer (GameMain/Domain) with actors, attacks, items, tiles, traps, and collision shapes; a gameplay layer (Level, WorldGenerator, LevelPlayerManager); a services layer for texture and audio loading, a 2D camera, animation, and GUI; and a screen system on top.

Screen management — a ScreenManager owns a stack of GameScreen objects (menu, loading, gameplay, pause, game over) and handles the transitions and input routing between them, so each screen stays self-contained.

State pattern — enemy AI is modelled as explicit states behind an IEnemyState interface (patrol, chase, attack), with a separate set per enemy type: ghost, spider, and witch. The player characters use the same approach behind IActorState / IPlayerState. Behaviour changes by swapping the active state object instead of branching on flags.

Factory pattern — an EnemyFactory centralises enemy creation, so the rest of the game asks for an enemy type and gets a fully wired instance back. Collision is handled through a small hierarchy of hit shapes (RectHitShape, CapsuleHitShape) behind an IHitShape interface.

It began as a working game and is still being extended — the focus is on learning where each design pattern actually earns its place in a real codebase.
